Method

This page tells you where each figure comes from, how this site calculates it, what it cannot show, and how to get the data.

Scope

This site is a record of the hazard events of New York City. For each event it gives the weather, the water levels, the reported consequences, and the federal assistance. Each figure has its source, its period, and its status.

This site is a reconstruction from published federal data and city data. It is not an official record. It does not rank events.

What an event is

NOAA publishes a Storm Events Database. One row is one hazard type, in one place, over one time window. A cold spell in January 2000 is five rows, one for each borough. The Weather Service groups those rows into an episode. An episode is one weather system.

An event on this site is an episode. This project tested that rule. The four episodes in January 2000 match the first four events in the tool of the City exactly.

Hurricane Sandy is the exception. The Weather Service filed it as two episodes: a coastal flood and a high wind. An automatic merge of overlapping episodes gave 982 events at zero tolerance, and 614 events at six hours. That result is too sensitive for the primary unit of a site. Thus a person declares each merge. There are very few merges, and a merged event says so at the top of its page.

Places

The source files a location as a county or as a forecast zone. The type depends on the event type. Counties alone lose most winter events, heat events, and wind events. This site uses both types, and 12 codes in total.

Queens was one zone. It then became Northern Queens and Southern Queens. Thus Queens can occur two times in one episode, and geography below the borough level exists for Queens alone in the later period. The borough is the only correct level for the full record.

New York Harbor is inside the waters of the City. This site carries it as its own place. It does not carry the adjacent marine zones.

This site joins on codes, never on names. The same marine zone occurs as NEW YORK HARBOR and as New York Harbor in different years.

The event record

NOAA Storm Events, from 1950 to the present day. The narratives, the hazard types, the death counts, the injury counts, and the damage estimates are the data of the Weather Service.

The database holds each event type only from 1996. Before 1996 it holds tornado, hail, and wind alone. An event page before 1996 tells you this.

Weather

Daily summaries from the Global Historical Climatology Network, at Central Park, LaGuardia, John F. Kennedy, and Newark.

  • A high or a low is the most extreme daily reading at one station. The station and the date are with it. It is not a citywide figure and not an average.
  • This site adds the rainfall totals and the snowfall totals at the wettest station. It never adds them across stations, because that counts one storm four times. The note gives the number of days that the station reported.
  • The wind figure is the fastest two-minute wind, GHCN element WSF2. It is not a gust. The peak gust is element WSFG, and these four stations do not report it.
  • This site uses daily summaries, not hourly summaries. The hourly files are about seven megabytes for each station-year, or about two gigabytes here. The site reports these measures as event peaks. The cost of this decision is that it cannot calculate the rainfall rate or the heat index. Thus it does not offer them.

Water levels

NOAA tide gauge readings at The Battery, on the mean lower low water datum, in Coordinated Universal Time.

This site reads the water levels only if the event has a coastal hazard. An inland heat wave has no tide panel, and its comparison cell says "not read here". It is not blank.

Radar

Composite reflectivity tiles from the Iowa Environmental Mesonet at Iowa State University. Two products cover different halves of the record, and the site gives the name of the product that it shows. This is a national composite. It is not the view of one radar of the city.

The browser reads the tiles live from the archive. It does not copy them. Thus the radar panel depends on a different service. If that service does not answer, the panel tells you. An absent reflectivity layer is not clear weather.

The frame step becomes larger for a long event. Thus a drought of two weeks does not request thousands of tiles.

Federal assistance

The federal government obligates assistance against a declared disaster, not against a storm. A declaration has its own incident period, and it can cover several events on this site. DR-1083 matches 14 events. The same total then occurs on each of those 14 pages, because that is what the source publishes. It is not the money of 14 storms.

For this reason, no page ranks or sorts events by assistance. The explorer carries a count of declarations, not a column of dollars. Each assistance figure gives its declaration and the number of events that share it. The comparison sheet groups those rows under the declaration.

  • This site matches a declaration on an overlapping incident period. It uses weather incident types only, and periods short enough for one storm. Without that limit, the COVID-19 declarations attach billions of dollars to each storm for three years. Their incident period is 1,207 days. The build now fails if it attaches a declaration with a long period.
  • Public assistance is the federal share obligated for the counties of New York City. It is money committed, not money spent, and it is not a measure of loss. Obligations continue for years. Thus a total is correct only on the build date.
  • Housing assistance is the amount that the Individuals and Households Program approved for the ZIP codes of New York City. Owners and renters are separate programs for separate populations. This site adds them together and tells you.
  • A flood insurance claim is different. A claim has a date of loss. Thus it joins to the event window. Claims also exist for events with no declaration.

Consequences

311 service requests and police collision reports.

311 is eight datasets, divided by period, and the complaint vocabulary changes between them. This site gets the counts as daily totals by borough, not as rows. There is no 311 record before 2004.

These counts measure the reporting as well as the effect. A neighborhood that calls 311 more often appears to flood more often.

Calculation

Hazard names

The source publishes 26 event types for New York City. Several of them are marine versions of a land type. This site folds them into 18 hazard values. That fold is the only change of this project to the vocabulary. If a source type has no mapping, the build fails. It does not put the type into an "other" group.

There is no level above those 18 values. An earlier version grouped them into Water, Winter, Temperature, and Wind. No source publishes those groups, and they put drought under Temperature. The groups and their colors are removed. The explorer lists the hazard values with the number of events for each one.

Consequence windows

The windows are not the same for each source, and this site does not treat them as the same.

  • 311 counts run over the event window and the next day, because a person often files a complaint about a storm on the next morning.
  • A collision has a timestamp of the event itself. Thus this site counts collisions inside the window only.
  • A flood insurance claim follows the 311 rule.

Each panel gives the window that it used.

Storm surge

The source does not publish storm surge as a measurement. This site calculates it: the observed level minus the predicted tide. It labels the result as derived in each place that the result occurs.

Dollars

Each dollar figure occurs two times: as published, and adjusted to dollars. This site adjusts with the consumer price index of the Bureau of Labor Statistics for New York-Newark-Jersey City, series . It uses the metropolitan series, not the national series. The national series is too low for a loss in New York.

Absences

This site never shows a number that no person measured as a zero. The tool that this project rebuilds prints 0 % absent for school attendance during Hurricane Sandy. Schools were closed for a week.

Each measure carries one of five statuses. The statuses go into the downloads as their own columns. A spreadsheet with an empty cell for "nothing happened" and also for "no person looked" has the same fault in a different container.

Not collected is the usual case, not the rare case. Collision records start in July 2012 and 311 records start in 2004, against an event record that starts in 1958. The build fails if no measure in it is marked not applicable, because that result means the site lost the difference.

Limits

This project could not rebuild four capabilities of the tool of the City from public data. They are absent from each event, for the same reason each time. Thus this page gives them one time. It does not repeat them under 900 events.

  • School attendance. Schools supply the daily present counts, absent counts, and released counts to the City directly. The City does not publish them.
  • Power outages. Utilities report to the New York State Department of Public Service under a data sharing agreement. No public historical series exists at the borough level or below it.
  • Sanitation operations. Salt usage and plow data are public. Collection tonnage and equipment deployment are not public. Two measures of six under one heading would mislead you.
  • Subway ridership. Daily public figures start in 2020. No public source gives station-level ridership before that year.

These things are also absent: events before 1950, which the tool of the City offers back to 1785 from a source that this project cannot identify; flood sensors, which start in approximately 2021; air quality, which the City publishes at the county-day level, and which is coarser than an event chart implies; and NYCEM activation records, which are operational and unpublished.

Known differences

The tool of the City reports 2,431 events. The New York City land records in Storm Events are 2,097. With the New York Harbor marine zone, they are 2,392. This project cannot account for the other 39. That number agrees with entries from before 1950, but no source confirms it.

For Hurricane Sandy, the Storm Events records inside the event window carry 45 direct deaths. The tool of the City reports 43. Both figures have a defensible source. This site shows the figure of its own source and gives the difference. It does not reconcile the two figures quietly.

Dictionary

Event
One episode in the NOAA Storm Events Database. An episode is one weather system. It is the primary unit of this site.
Episode
The group that the Weather Service makes from its own rows. One episode holds one or more records.
Evidence row
One record in the Storm Events Database: one hazard type, in one place, over one time window. An event holds one or more of them.
Hazard
One of the 18 values that this site folds the 26 source event types into. There is no group above these values.
Status
The word beside a measure that tells you the type of the value. Each measure has one of five statuses, and each status has its own column in the downloads.
Derived
A value that this site calculates, and that no source publishes. Storm surge is derived. This site labels each derived value.
Declaration
A federal disaster declaration, with its own incident period. The federal government obligates assistance against a declaration, not against an event. One declaration can cover several events.

Build

Eight sources, five Python stages, one archive. The diagram comes from the same configuration that the pipeline runs on.

The five stages use the Python standard library. There is no install step and no virtual environment. The site is then static HTML, CSS, and JavaScript, with no framework and no build step, served as files on GitHub Pages.

  • 01_fetch downloads each source. It then checks that the result is what the next stage needs. A moved NOAA file and a FEMA outage both answer HTTP 200 with an HTML error page.
  • 02_normalize makes the canonical tables: event rows, events, station-days, and track positions.
  • 03_enrich attaches the 311 counts, the collisions, the water levels, and the federal assistance. It is the only stage that returns to the network after the event list exists.
  • 04_validate tests the grains. It does not trust them. It checks referential integrity in both directions, and it fails if a figure is wrong. It does not warn.
  • 05_export writes the site data and the downloads into a staging directory. It then moves them into place in one step. It does not run if validation failed. Thus a bad build does not change the published files.

The file pipeline/00_config.py holds each tunable value: the source URLs, the zone and county mapping, the hazard vocabulary, and the validation thresholds. A failure stops the build, and it never reaches this page. The list below is what the last build found and allowed.

Reuse

The compiled data is free to use, but you must give attribution. The source data carries the terms of the agencies that publish it. If you republish a figure, carry its status and its period with it.

If you find an error, report it.
